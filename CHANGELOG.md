## Unreleased

### Session export (0.6-F)

- **`tabcap session export --for requests|httpx|playwright --out <file> [--origin <url>] [--tab t2]`** hands the logged-in tab's session to a script: its cookies (`Network.getCookies` for the origin, plus the session's own browser context for a pool account), the headers its page sent to authenticate (from the latest recorded request to the origin's host that carries one: sensitive headers by the `bundle redact` rule plus `x-csrf*`, `x-xsrf*`, `*-token`, `*-auth*`, `api-key`, and any header the page set that is not a browser default; `cookie` goes with the cookies, `proxy-*` never) and its localStorage / sessionStorage, read in tabcap's isolated world (values over 64 KB skipped and listed). Without a recording `headers` is empty and `source.headers` is `none`, with a hint to run `net start` first.
- Formats: `requests` is JSON (schema `tabcap-session-export/0`: origin, capturedAt, cookies, headers, storage, note); `httpx` is an importable Python module (`.py` added when missing) with `cookies`, `COOKIE_RECORDS`, `headers`, `storage` and `client(base_url)`; `playwright` is the `replay session` storageState, with headers and sessionStorage reported as `omitted`.
- The file is mode 0600 (new directories 0700) and holds live credentials; the answer carries the path, counts and header names only (`{file, for, origin, mode, cookies, headers, storage, source, note}`), and the bundle gets the usual `cmd` events with counts.
- `replay export-python` packages now ship `_tabcap_session.py` (load the JSON export, build an httpx client; no tabcap at runtime), and their README says how to use it.

### Requests through the logged-in tab (0.6-A)

- **`tabcap fetch <url>`** sends a request from the session's tab and records it (needs `net start`): the page's own `fetch()` with `credentials: "include"`, run in a tabcap isolated world of the tab's main frame, so it carries the page's cookies and obeys the page's CORS rules. `--method`, `--header k:v` (repeatable), one of `--body <text|@file>`, `--json <text|@file>`, `--form k=v` (repeatable); `--tab`, `--timeout` (covers the wait for the host's turn). The answer: `{id: "r-N", fetchId: "c-N:f-K", status, statusText, mime, bytes, headers (content-type, content-length, content-encoding, content-disposition, location, cache-control, etag, last-modified, retry-after; scrubbed), body (text up to 8 KB) | bodyFile, timing: {startMono, endMono, ms}, waitedMs}`; `--out <file>` writes the body to that file, `--raw` returns it as `bodyBase64` (up to 16 MB). Text bodies are secret-scrubbed wherever they go.
- **Deterministic attribution**: every recorded request of a fetch carries `fetchId`, and its `cmd` is that fetch's own command window even when several commands are open at once. Same-origin requests carry a marker header (`x-tabcap-fetch`) that the recorder removes at Fetch's Request stage before the request leaves Chrome (the server never sees it; the recorded headers do not have it); cross-origin requests carry no marker (it would force a CORS preflight) and are recognised by the helper's unique function name and scriptId on the initiator stack. The `cmd` end event of a fetch lists its `r-N` in `outputSummary.requests`.
- **Pacing per host**: `config.json` `fetch: {minIntervalMs: 3000, concurrency: 1}`, overridable per store site under `sites.<name>.fetch`; requests to a host queue in arrival order, `waitedMs` reports the wait, and there is no flag to skip it.
- **Stop rules**: `--stop-on` (repeatable, after `config.json` `fetch.stopOn`): `empty-body`, `status>=<n>`, `status=<n>`, `json:<$.path>=<value>`, `json:<$.path>!=<value>`, `text:<regex>`. When one fires the response is recorded, the command fails with `fetch.stopped` (rule, detail, `request`, and the whole answer as `result`), a `guard` breaker event with reason `fetch-stop` is written, and further fetches to that site fail with `guard.stopped` until **`tabcap guard resume --site <site>`** (new) or, if the session is waiting for the human, `handoff continue`. The session is not put into `waiting`.
- A fetch the page's CORS rules block fails with `fetch.blocked`, carrying Chrome's console message. `fetch` waits like other page commands while the session is handed to the human, and counts against an account's hourly budget.
- **`tabcap fetch --batch <file.jsonl>`**: one request per line, sent in order under the same limits in one command (`fetchId` `c-N:f-1`, `f-2` …), one envelope printed per line.
- **`POST /fetch`** on the daemon's own listener (the Unix socket; on Windows loopback TCP with the bearer token): `{session, tab?, url, method?, headers?, body?|json?|form?, timeoutMs?, stopOn?, rawBody?}` → the same envelope. `replay export-python` writes **`_tabcap_fetch.py`** next to the client, a small httpx helper for it (`TabcapFetch(session).fetch(url, …) → (status, headers, bytes)`), documented in the generated README as "Route an existing scraper through the browser".
- `net start`'s `instrumentation` note says that during a same-origin fetch the tab's fetch() requests also pause at the Request stage.

### Daemon fixes from a real-project test (0.6-D)

- **DOM-backed refs**: an element that `snapshot --css` / `--xpath` matches but that has no accessibility node (UI libraries hide inputs and buttons from the tree) now gets a ref too, printed as `(no accessible node) <input#id.class> [e31]`: bound to its backend node id, frame and loaderId like any ref and expiring the same way. `click`, `fill`, `type` (after a `fill` / `click` focused it), `hover`, `upload`, `html` and `screenshot --ref` take it. `search.domRefs` counts them.
- **Click effect**: after a default (DOM) `click`, the answer says what happened within the post-action wait: `effect: "dom" | "navigation" | "request"` (the first observed), or `effect: "none"` with a `note` suggesting `--trusted` when the page did nothing (a handler that only reacts to trusted input). Observe-only (a MutationObserver in tabcap's isolated world, Page / Network events; without a recording Network is switched on for the watch only); the exit code does not change; `--trusted` and `--no-wait` report no effect.
- **`find` searches child frames**: the root document and every frame of the frame tree; hits in a frame carry `frame` and frame-path refs, the answer `frames` (frames searched). `where` reads the page text of all frames too when it decides the date order.
- **A POST answered with a redirect keeps its body**: the recorder wrote the redirected hop without its request body (`postData: null`); it now stores it under the usual rules (inline up to 64 KiB, else a blob), and the next hop's `redirect.from` still points at it.
- **Image captcha advisory**: an image captcha next to a login form (image src / id / class / alt / label mentioning captcha / verify / 验证码 / 校验码, or an input named like captcha / vcode / verifyCode) adds a `challenge  image-captcha img [e12] → input [e13]; …` line to the `snapshot` / `outline` header and `challenge` to their JSON, `challenge: {kind, image, input}` to `fill` / `click` on that form, and one `guard` event `{event: "challenge", detail: {kind: "image-captcha", advisory: true, …}}` per page. Nothing waits and nothing is refused: the model reads the image (`screenshot --ref`) or asks the human. Other challenges still hand over as before.
- **One browser context per account**: every `session start --site <s>` with an account (also `--account auto`, also accounts without a pool proxy) gets its own browser context, with the account's cookies restored at start and written back as for pool accounts, so a second account never finds the first one logged in. Sessions without an account use the default context.

## 0.5.0 (2026-10-16)

### Changed

- **Output budget** (0.5-C): when a command's `data` is over `TABCAP_OUTPUT_LIMIT` bytes (default 16384; `0` turns it off), the whole `data` is written to a file and the answer is `{summary, file, bytes, truncated: true}`. The file is `exports/<command>-<seq>.json` in the session's current recording, else `<cache>/outputs/<stamp>-<command>.json` (0600). The summary keeps every scalar top-level field and gives arrays, objects and long strings by their length; `analyze deps` adds the inputs per request and the unresolved count, `recon` its dossier summary, `trace list` the API × script counts, `where` the top 5 candidates. `--full` prints everything. `net list`, `console list`, `snapshot` and `schema` are exempt.
- **Output filters on every command**: `--select <path>` (dotted keys, `[n]`, `[*]`), `--grep <regex>` (array elements whose JSON matches; long or multi-line text fields: matching lines with `line` numbers and `--context n` lines around them; at most `--max-matches 50`; the regex is at most 256 characters, `u` flag) and `--fields a,b,c` (project array elements). They run in the CLI before the budget, in that order; the envelope then carries `filter: {select, grep, fields, matches, total, capped}` (and `selected` with `--select`). `tabcap schema --json` lists them once under `sharedFlags`.
- **`tabcap --help` is an index**: one line per command, grouped like the command reference, summaries cut at 60 characters, under 6 KB. `tabcap help <command>` prints that command's full help (as `tabcap <command> --help`); `tabcap help <group>` (e.g. `network`, or a command word such as `net`) the full help of every command in it.
- Defaults: `net list` and `console list` return 30 rows per page (was 100; `--page-size 0` still returns everything); `snapshot` (and `--snapshot` on actions) cuts at 12000 characters (was 60000), and a cut `snapshot` or `outline` says how to get more (`--max-chars`, `--interactive`, `--frame`).
- The skill: `SKILL.md` is under 8 KB (rules, the record → analyse → replay loop, credentials, handoff, the output budget and a 10-line cheat-sheet); the rest moved to topic files under `references/` (`recording.md`, `analysis.md`, `pools.md`, `trace-and-probes.md`, `replay.md`, `mcp.md`). `bun run validate:skill` checks the 8 KB.
- Credential rule: storing a password once is recommended for the human (`site add` / `account add` at a prompt or with `--password-stdin`), but no longer reserved to them: an agent the user hands a value to may store it once with `--password-stdin` (no terminal needed), and from then on only the `<secret:…>` references are used. The help of `site add`, `account add` and `proxy add`, the skill, docs/04 §8.1 and the README say so; the code already allowed it.
- README: the five differences describe 0.4 (credentials stored once then referenced; the plugin interface for your own challenge handlers next to "ships no solvers"; `where`, `analyze deps` / `chain`, `export-python` `verify()`, `recon`, trace mode and the two probes), and the Chinese README carries the same information as the English one.

### MCP server (0.5-A)

- **`tabcap mcp`**: a Model Context Protocol server on stdin / stdout, written by hand (JSON-RPC 2.0, one message per line, no new dependency): the initialize lifecycle of MCP 2025-11-25 (also answers clients asking for 2025-06-18, 2025-03-26 or 2024-11-05 with their version), `ping`, `tools/list`, `tools/call`; only MCP messages on stdout, logs on stderr; it exits when stdin closes, after the calls in flight have answered.
- **Tools are generated from the command table**, in two sets, because hosts load every tool definition into the model's context: by default a **core set of 24 tools** (8.5 KB of definitions) — `session start` / `stop` / `list`, `navigate`, `snapshot`, `outline`, `click`, `fill`, `type`, `press-key`, `hover`, `wait`, `screenshot`, `evaluate`, `net start` / `stop` / `list` / `show` / `body`, `handoff status` / `continue` with one-line descriptions and bare property schemas, `tabcap_handoff_wait`, **`tabcap_run {argv}`** (any other command, argv as on the command line) and **`tabcap_help {command?}`** (the command list with usages and the tool for each, or one command's help text and schema entry); **`tabcap mcp --all-tools`** lists one tool per command with the full help texts instead (83 tools, 58 KB). A command tool is named `tabcap_` + the command path with spaces as `_` (`tabcap_navigate`, `tabcap_net_list`, `tabcap_press-key`); `inputSchema` comes from the positionals (choices → `enum`) and the long flags in camelCase (`--page-size` → `pageSize`, repeatable → string array); every daemon command takes `session` and `timeout`. Neither set has, and `tabcap_run` refuses: `mcp`, `daemon run`, `site add` / `proxy add` / `account add` (they read a password from stdin, which is the MCP channel), and the foreground servers `fingerprint serve` / `wire serve` / `replay serve`; `schema` has no tool of its own; the print-format flags `--text` / `--json` are left out because a tool always returns the envelope.
- **`tools/call` runs the command in-process through the CLI's own `run()`** (no shell, the same parsing, validation and secret scrubbing) and returns the envelope, pretty-printed, as the only text item, with `isError: true` when `ok` is false; arguments that do not fit the schema are a `usage` envelope too. A handed-over session is not waited for: the `waiting` error comes back at once with its `next`; **`tabcap_handoff_wait {session, timeoutSeconds ≤ 300}`** polls `handoff status` once a second and returns as soon as the human has continued, or the `waiting` error again when the time is up.
- **`tabcap mcp --print-config <host>`**: the config file(s), the entry and the host's own add command for `claude-code` (`claude mcp add tabcap -- tabcap mcp`), `cursor`, `codex` (TOML), `gemini-cli`, `windsurf` and `claude-desktop`, checked against each host's official page on 2026-10-16 (`verified: false` for windsurf, whose page now redirects to Devin Desktop's).
- `analyze diff`'s trailing bundles are a list: the usage line reads `[<bundles>...]`.

### Body export (0.5-F2)

- **`tabcap net body <r-N | --url u> --file [--pretty]`** writes the decoded body (charset-decoded, content-decoding undone, exactly what `--grep` / `--lines` search; `--pretty` applies the same line-breaker) to a file and answers `{id, url, mime, bytes, lines, pretty, file, scrubbed}`, with no body inline, so an agent with a shell can run `rg` / `grep` on the path. The file is `exports/bodies/<r-N>[.pretty].<ext>` (ext from the MIME type: js, json, html, css, txt, else bin) in the session's open recording, else `<cache>/outputs/bodies/<stamp>-<r-N>…`; mode 0600; a repeat overwrites. Known secret values are replaced by `<secret:…>` before the write (`scrubbed: true`); a binary body is written as recorded and reports `scrubbed: false` with a note. `--file` cannot be combined with `--grep` / `--lines` / `--at` / `--out` (usage error).

### In-command search (0.5-F)

- **Snapshot filters**: `snapshot --grep <regex>` prints only the lines whose role, name, value, states or description match, each with its ancestor lines indented as in the full tree (`--context N` adds N siblings each side, `--max-matches` 50 by default); `snapshot --css <selector>` / `--xpath <expr>` resolve in each shown document in tabcap's isolated world and print the matched elements' lines with ancestors (`(no accessible node) <tag#id.class>` when an element has none); `snapshot --ref e12 --depth n` prints the subtree under one element (its own frame for a frame ref). They compose with `--frames` / `--frame` and `--interactive`; refs are the full snapshot's, the header stays, `search` reports matches / shown, and every cut says how to get more. Regexes: JavaScript, `u` flag, at most 256 characters; an invalid one is a `usage` error.
- **`tabcap html <ref | --css selector> [--inner | --text | --attrs] [--max-chars 4000]`**: one element's outerHTML, innerHTML, textContent or attributes, read in the isolated world (frame refs read in their frame), secret-scrubbed before the cut; `truncated` and `chars` say when it was cut. It writes only the usual `cmd` events.
- **Body line search**: `net body r-12 --grep <regex> [--context 3] [--max-matches 50]` returns `{line, col, text, before, after}` per match on the decoded body (UTF-8, else the response charset), with `lines`, `bytes`, `mime`; `--lines a-b` returns a range (500 lines per call at most, `note` names the next one); `--at line:col [--context 5]` returns the lines around a raw-body position, as `trace list` and console stack frames give it, and `--url <script url>` finds the request by URL instead of an id. Long lines come back as a 500-character window (`clip`).
- **`--pretty`** on `net body` / `net grep`: JavaScript bodies get line breaks after `;`, `{`, `}` and `,` outside brackets, strings, template literals, regex literals and comments (a small tokenizer that only inserts text, so `--at` positions map into the pretty text); JSON bodies are re-indented; bodies over 8 MB are not prettified, and the answer says so.
- **`tabcap net grep <regex> [--resource-types …] [--max-matches 20] [--context 1] [--pretty]`**: raw-text search over every recorded response body of the session: per request `{request, url, resourceType, count, matches}`, at most 50 requests (`more`), bodies over 8 MB under `skipped`. Distinct from `analyze find`, which follows values through decode chains.
- `net body`'s id is optional now (give it or `--url`); the MCP tool table keeps `html --text` (its key is `textContent`), since only print-format `--text` / `--json` flags are left out.

### Added

- **npm packaging script**: `bun run npm:pack [--version X] [--targets a,b]` assembles the four platform packages (`tabcap-<os>-<cpu>`, or `@tabcap/<os>-<cpu>` by flipping one constant) and the `tabcap` package (shim, skill, README) from the release binaries into `dist/npm/`, packs them offline with `SHA256SUMS`, and prints the publish order; `packaging/npm/README.md` is the local install check and publish runbook. Nothing is published.

## 0.4.0 (2026-10-16)

### Frames: frame-path refs (0.4-I)

- **The frame tree is in the snapshot header**: `snapshot` and `outline` list every child frame (iframes and frameset frames, cross-origin ones too) as `frames` lines, `f2/f1  <url>  same-origin|cross-origin  depth 2  "<title>"`, indented by depth; `n` in `f<n>` is the frame's position among its parent's child frames in document order. The JSON has a `frames` list (path, url, origin relative to the parent frame, depth, title). A page without child frames answers exactly as before.
- **`snapshot --frames`** also expands each frame's tree, **`snapshot --frame f2/f1`** only that frame and its descendants (the root document stays a header). Elements in a frame get **frame-path refs**: `f<n>/e<m>`, nested `f<n>/f<k>/e<m>`; `--max-chars` applies per frame, and a frame that overflows ends with a `(truncated)` line.
- **Every ref-taking command takes frame refs**: `click` (also `--trusted`), `fill` (also `--trusted`), `hover`, `upload`, `where`, `screenshot --ref`, `evaluate --function … --args '[{"ref":"f2/e7"}]'` (the function then runs in that frame's window). Same-origin frames resolve through the tab's session, out-of-process iframes through their own; trusted mouse input goes to the tab with the point moved by the frame's offset chain, after an occlusion check in the frame and at each frame's owner element. A frame ref expires when its frame navigates (`stale-ref` names the frame); a ref with the wrong frame path says which ref that element number belongs to. Outputs of actions on frame refs carry `frame` (also in the `cmd` end event's `outputSummary`).
- **Overlays in frames**: the overlay header also looks into child frames (`in f2`), and an overlay with an iframe (an iframe layer) lists the close button inside its iframe with its frame-path ref, so the layer can be closed with `click`. `click` / `fill` on a frame ref also fail with `covered` when an overlay of an ancestor document covers the frame.
- `type` follows focus into frames (same-origin through the page, cross-origin through the frame's session) to mask text typed into a password field there.
- The range gets docs/05 s22 frames (frameset, cross-origin iframe with a nested same-origin frame, an iframe layer with its close button inside a cross-origin iframe).

### Recon dossier v0 (0.4-J)

- **`tabcap recon [--text]`** and **`tabcap analyze recon <bundle> [--text]`** (offline, the last recorded document stands in for the page): a dossier of the session's recording and current page, written into the bundle as `exports/dossier.json` (schema `tabcap-dossier/0`) and `exports/dossier.md` (0600, overwritten on every run); the command prints the two paths, a short summary and `receipt: {dossier: "exports/dossier.json"}`, which the `cmd` end event keeps in `outputSummary.receipt`. It never sends a request. Four answers:
  - **Stack**: every adapter `detect` result for the current page, plus hints from a fixed table of 17 markers (headers `server`, `x-powered-by`, `x-aspnet-version`, `x-aspnetmvc-version`, `x-generator`, `x-runtime`, `x-nextjs-cache`; session-cookie names such as `JSESSIONID`, `ASP.NET_SessionId`, `PHPSESSID`, `laravel_session`, `csrftoken`, `_<app>_session`, `connect.sid`), header values as seen, cookie names only, graded 推断, no version guessing.
  - **Data channels and coverage**: requests grouped by method, path template (numeric, uuid and long-hex segments as `{id}`), resource type and body class (`json | html | fragment | text | binary | ws | sse`), with count, first `r-N`, statuses, `unreadByPage`, decode steps and the page tokens each carried; coverage is the share of the page's visible text tokens (4+ characters, numbers of 4+ digits) found with `analyze find`'s exact matching in recorded responses and received WebSocket frames, with up to 20 tokens that were not.
  - **Cookies**: per name the origin (`set-cookie` by `r-N`, present at session start, unrecorded), lifetime, flags, a role from a name table (`session`, `csrf`, `consent`, `analytics`, `load-balancer`, `unknown`; 推断) and `requiredBy` from `analyze deps` (graded as deps grades it); csrf-named request headers and fields are listed with their deps origin.
  - **Protection**: the guard's challenge detections (kind, `r-N`, what was handed to the human) and response signals (HTML 403, 429, `retry-after`, rate-limit headers, four bot-management header names), names only, 推断. Identification only, never a bypass hint.

### Wire probe (0.4-W2)

- **`tabcap wire probe --client <export-python dir> [--port <p>] [--samples <n>] [--text]`**: which network layer a generated Python client differs in from the Chrome for Testing tabcap launches, measured on a local TLS echo at 127.0.0.1. The client's new `uv run client.py wire-report --url … --ca … --out …` sends one GET (its own `Session()`, the echo's CA as `SSL_CERT_FILE`, no proxy for loopback); the component's `check` and `diff` compare it with the browser baseline. Output schema `tabcap-wire/0`: `browser{version, flagsHash, profile, cached}`, `client{library, version}`, `layers[{layer: tls|h2|headers, verdict: same|differs|missing, fields[{field, browser, client}]}]`, `checks[{code, status, message}]`, `labels` (`psk` when only one side resumed a TLS session) and a fixed `note`; `--text` prints a table. While the session records, the four documents (browser report, client report, check, diff) go into blobs and each differing layer becomes a `finding` with `tool: "wire"`, grade `实测`. Diagnostic only: it says which layer differs, never why a site refused anything, never how to change a value.
- **`tabcap wire profile [--samples 3] [--port <p>]`**: the browser baseline. A background tab of the session (the Chrome for Testing tabcap launched, with tabcap's own flags) ignores certificate errors for itself only (`Security.setIgnoreCertificateErrors`), navigates to `https://localhost:<p>/` and runs a page `fetch("/fetch")`, N times each, and closes again. The component's `profile` keeps navigation and fetch as two header-order roles (`http.roles`); tabcap adds a `tabcap` section (CfT version, the launch flags with machine paths replaced and their sha256, sample counts). Written to `cache/wire/profiles/cft-<version>-<os>-<arch>.json` (reports in `.samples/`) and reused by `wire probe` while version and flags hash match. The macOS arm64 profile of CfT 155.0.8059.79 is committed as `native/wireprint/corpus/chrome/155/macos-arm64/155.0.8059.79.json`; CI e2e jobs upload theirs as `wire-profile-<os>` artifacts.
- **`tabcap wire serve [--port <p>] [--capture-dir <dir>]`**, **`wire version`**, **`wire ca-path`**: the echo on its own (prints `{url, port, caPath}`, answers every request with the JSON report of its own connection until Ctrl-C), the component's version / path / sha256, and the echo's test CA (`src/wire/certs/`: CA + leaf for localhost, 127.0.0.1, probe.test with Authority Key Identifier; the private key is public by design and only serves 127.0.0.1).
- **The echo** (`src/wire/echo.ts`): a `Bun.listen` front records each connection's bytes up to the complete ClientHello and relays the stream unchanged to an internal `node:tls` server (ALPN h2, http/1.1; no session tickets: `SSL_OP_NO_TICKET`, `sessionTimeout: 0`, measured: Chrome then sends no pre_shared_key); h2 up to the first HEADERS block or the HTTP/1.1 head go to the component's `report`.
- **The component is embedded**: `bun scripts/native.ts build` cross-compiles `native/dist/<target>/wireprint[.exe]` for aarch64-macos, x86_64-linux-gnu, aarch64-linux-gnu and x86_64-windows-gnu (ReleaseSafe, stripped: 0.55 / 0.70 / 0.57 / 0.97 MB); `scripts/release.ts` builds them before `bun build --compile`, which embeds all four (the tabcap binary grows by about 2.8 MB). At run time the host's binary is extracted to `cache/native/wireprint-<sha256>/` (0700 / 0755) and its sha256 is checked before every spawn; a source checkout uses `native/dist/`, built with Zig 0.16.0 when missing. The release workflow sets up Zig; CI's native job builds all four and runs the host one, the e2e jobs build the host target.
- **Generated client**: `client.py` has one `__main__` with the subcommands `verify` (chain mode, unchanged usage) and `wire-report`.
- **`native/wireprint` changes** (docs/11): new `report --client-hello <file> [--h2 <file> | --h1 <file>] [--alpn] [--sni] [--peer]` (one per-connection report, the shape `profile` / `check` / `diff` read; HTTP/1.1 heads are parsed too). Exit codes: 0 ok, 1 usage or input error (message on stderr, nothing on stdout), 3 `check` INCONSISTENT (JSON still on stdout); `check` now prints JSON. `profile` writes `extension_order: randomized | fixed | unknown` (unknown with fewer than two samples judged; `extension_order_randomized` is then null) and `check` skips T4 for unknown; `--server` / `--server-host-os`. `diff` normalises two reports (GREASE stripped, extension set instead of the permuted order, PSK presence as a `psk` label, per-connection values listed as `ignored`; `--raw` keeps everything) and gains `--json`; SETTINGS pairs compare as one list. The OpenSSL `serve`, the `openssl` build option, `tools/serve-smoke.sh` and `tools/capture.sh` are deleted; `-Dstrip` is new; all three OSes run the same test set. The corpus takes only Chrome for Testing captures made by `tabcap wire profile`.

### Signal probe (0.4-G)

- **`tabcap fingerprint probe [--ref <name>] [--text]`**: the values this browser presents for a fixed list of 49 fields (navigator, UA client hints with the documented high-entropy hints, screen, devicePixelRatio, time zone, canvas and audio renders as sha256 of their bytes, WebGL parameters and extensions, speech voices, 30 font families through `document.fonts.check`, notification / geolocation permission state, color-scheme and reduced-motion media queries). Field names are the trace signal list's IDL names. tabcap serves its own self-contained probe page on 127.0.0.1 (port 0), opens it in a new background tab of the session, closes the tab afterwards and keeps the session's current tab. While the session records, a `state` event `{what:"env", source:"fingerprint-probe", fields}` goes into the bundle. JSON envelope by default (schema `tabcap-fingerprint/0`: `browser`, `ref`, `fields:[{name, value, ref, verdict}]`, `summary`); `--text` prints a table.
- **References are your own captures**: `tabcap fingerprint serve [--port <p>] [--once] [--force]` serves the probe page on 127.0.0.1 for your own browser; open the printed URL by hand and press "Save as reference" to write `config/fingerprint/refs/<name>.json` (0600 in 0700 directories; names `[a-z0-9-]{1,40}`; an existing name is refused without `--force`). `fingerprint ref list | show <name> | remove <name>`. Nothing is captured through CDP and no reference ships with tabcap.
- **`--ref <name>`** adds the reference column and a verdict per field: `same`, `differs`, `missing` (this browser lacks a field the reference has) or `extra` (this browser has a field the reference lacks); hashes compare as strings, arrays in order. **`tabcap fingerprint diff <bundle> --ref <name>`** compares the bundle's last `state` env event the same way, offline.
- Read-only analysis: the probe page only reads (no cookies, no storage), the output is a plain field table with no score, and nothing suggests how to change a value. `fingerprint probe` waits while the session is handed to the human, like `tab new`.
- Verdict direction (0.4-G2): `missing` now means this browser lacks a field the reference has and `extra` that this browser has a field the reference lacks (the first 0.4-G build had them the other way round).

### Account pool and proxy pool (0.4-D)

- **Proxies in the store**: `tabcap proxy add <name> --url <scheme://host:port> [--user <u>] [--password-stdin] [--bypass "<list>"]` (the password only from stdin or the prompt; a username with `socks5://` / `socks4://` is refused with `unsupported`, because Chrome offers no-auth SOCKS only), `proxy list` (name, scheme, host:port, user, hasAuth, bypass, state, last check; never the password), `proxy remove`, `proxy check <name> [--url <u>]`. A health check only contacts the address you give (`--url` or `config.json` `pool.health.url`); without one nothing is contacted and the state is `unchecked`. States: `unknown` → `up` on success, `down` after 3 failures in a row, rechecked after 1 / 5 / 15 min, back to `up` on one success.
- **Accounts bound to proxies**: `tabcap account bind <site>.<user> --proxy <name>|system|none`, `account list [--site]` (state, coolUntil, proxy, lastUsedAt), `account set-state <site>.<user> active|disabled`. Account states: `active`; `cooling` for 30 min after a guard breaker (the handoff still happens); `needs-human` after 2 failed logins within 24 h (a `--confirm`ed password retry counts as a failed login), cleared only by `handoff continue` or `account set-state … active`; `disabled`.
- **`tabcap account add <site> --user <u> [--password-stdin] [--totp-stdin]`** adds a second (third …) account to a stored site, so `--account auto` with `round-robin` / `lru` has something to choose from. Password from the prompt or stdin only, never an argument, never in the output; a duplicate `<site>.<user>` is a `conflict`. With `--totp-stdin` (needs `--password-stdin`) stdin is two lines: the password, then the TOTP seed. `account remove <site>.<user>` is its inverse (also drops the saved cookies and counters) and is refused while a running daemon has a session using the account.
- **`tabcap proxy set-state <name> active|disabled`** disables a proxy by hand (skipped by allocation and rotation, never checked) or re-enables it (back to `unknown` with the failure count cleared until the next check). Output `{proxy, from, state}`.
- **`session start <name> --site <s> [--account <user>|auto]`**: `auto` picks by `config.json` `pool.strategy` (`fixed`, `round-robin`, `lru`). The output and the bundle manifest (`session.proxy`) name the account and proxy. An account bound to a proxy gets its own browser context through it (Chrome only gets `host:port`), with its saved cookies restored; its cookies go back to the store on every cookie snapshot, at `session stop` and before the daemon closes the browser. One session per pool account at a time.
- **Proxy authentication** is answered by the daemon (browser-level `Fetch.authRequired`); while that handler is on, every command output carries `fetchAuth: "on"`. The proxy password, `user:pass@host:port` and `base64(user:pass)` (Chrome reports `Proxy-Authorization` in `raw/cdp.jsonl`) show as `<secret:proxy.<name>>` in every output, the daemon log and the bundle.
- **Egress policy and budget** in `config.json` `pool`: `egress: {mode: "fixed"|"rotate", rotateOn: "per-session"|"every:<N>requests"|"every:<T>min"}` (rotation is decided at session start), and an optional hourly request budget per account (`budget.requestsPerHour`, none by default): when used up, page commands answer `guard.budget` until the next hour. `guard` events `budget` and `breaker` are now written (docs/04 §4.2).
- **Downstream**: the generated Python client reads `TABCAP_PROXY_URL`; `replay export-python --proxy-env <file>` writes the bundle account's proxy URL there (0600, never printed); `replay check --live` goes out through the same proxy.
- Chrome for Testing now starts with `--disable-features=…,PreconnectToSearch`: a context with its own proxy otherwise sends `CONNECT www.google.com:443` through it on every navigation.
- New error codes `guard.budget` and `ext.no-context` (ext mode cannot give a proxy-bound account its own context; use direct). The store gets migration 3 (additive).

### Value-flow analysis and the action chain

- **`tabcap analyze deps <bundle> [--session name] [--request r-N] [--text] [--write-findings]`**: a deterministic dependency graph (schema `tabcap-deps/0`). For every request input (query parameters, form and JSON body leaves, `x-*` / `authorization` headers, cookies by name) it lists the sources found in earlier events, in priority order: an earlier response's `set-cookie`, a response body value (the JSON path through the `analyze find` decode chain, or a token inside HTML / text), a recorded `fill` / `type` value, the same value sent by an earlier request, a constant, a timestamp (the `analyze diff` classes). Matching is exact (trimmed; query / form values URL-decoded); a source counts only when it happened before the value was first sent. An input with no source is `computed-in-page` (with the diff hints and the inputs that vary with it) or, for cookies, `unrecorded`. `--secret` fills only ever match their `<secret:…>` placeholder, and the output never carries values. One JSON envelope by default like `find` / `diff` (`--text` for a report); the bundle is only read unless `--write-findings` appends `finding` events (`tool: "deps"`, `实测` only for sources re-read exactly from the bundle, `推断` otherwise).
- **`tabcap analyze chain <bundle> [--request r-N] [--session name] [--text]`** (schema `tabcap-chain/0`): the requests needed to reproduce one request (default: the last data-bearing xhr / fetch / document request), in recording order, with what each step provides to later steps and what it still needs from the caller; `todo` lists the `computed-in-page` / `unrecorded` inputs.
- **`replay export-python` follows the chain** when the graph links a request to an earlier response (`--chain` forces it, `--no-chain` keeps the 0.3 output, apart from the uv packaging under Changed): values from earlier replies become arguments, `computed-in-page` inputs become parameters defaulting to `TODO` (the comment names the hints and co-varying inputs), sensitive-named inputs (the `bundle redact` name rule) are never written out, and `client.py` gets `verify()`: `uv run client.py verify --base-url <url>` replays the chain step by step, compares each answer with the recording the way `replay check` does, prints a pass / fail table and exits non-zero on failure. The recorded expectations are in `verify_expected.json` (0600; secrets as `<secret:…>`, read from `TABCAP_SECRET_*`; a note on redacted copies). The caller fills TODOs in an optional `todo_inputs.py`; the README explains the loop.
- The generated docs keep an offline command's own `--session` flag (only the shared daemon `--session` / `--timeout` are left out of usage lines).

### Where a shown value comes from (0.4-C)

- **`tabcap where <ref|text> [--as ref|text] [--top 5] [--text] [--write-findings]`** (schema `tabcap-where/0`): which recorded response carries a value the page shows. A ref (`e12`, while the session's tab has a current snapshot) stands for its element's visible text; anything else is searched as typed (`--as` forces either). Candidates are JSON values through the `analyze find` decode chain (same paths and step names), the whole text of other text bodies, and the text nodes of HTML responses (a tag-path selector into the response source); JSON candidates come before HTML ones. `match` is `exact` (equal after trimming, score 1) or `normalized` (score 1 / (1 + rules used)); ties go to the earlier request. It reads only the session's recording (the bundle written so far, or the last one after `net stop`) and sends no request. The JSON envelope is the default; `--text` prints a report; `--write-findings` appends `finding` events (`tool: "where"`, `实测` for exact matches, `推断` for normalized ones).
- **Value normalisation** (table-driven, every plausible interpretation with the rule names used, fewest rules first): `trim`, `nbsp`, `html-entity`, `js-escape`, `fullwidth`, `thousands-sep` (`,` `.` `'` space, Indian `1,23,456`), `decimal-comma`, `accounting-negative` (`(1,234.56)`), `trailing-minus` (`1234.56-`), `trailing-zeros`, `date-yyyymm` (`2026-09` / `202609` / `09/2026`; full dates `20260915` / `15/09/2026` / `09/15/2026`), `dotted-code` (`1001.01` ↔ `100101`), `dr-cr`, `empty-zero-null`. An `a/b/YYYY` date with both parts ≤ 12 gets candidates only when another date on the same page proves the day / month order; otherwise `ambiguous` lists both readings (reason `ambiguous-date`). A query that is only empty / `-` / `—` / `null` / `0` returns reason `too-common`.
- Bodies that are not UTF-8 are decoded with their declared charset (response charset, content-type, else an HTML `<meta charset>`), e.g. GBK; an unknown charset gives reason `unsupported-charset` when nothing else matched.
- Range scenario s40 locale-numbers (en-US, de-DE, fr-FR, en-IN, accounting renderings of one `/api/rows`) in the end-to-end suite.

### Embedded state in HTML pages (0.4-H)

- **Three new decode-chain steps** for the state an HTML document carries, used by `analyze find`, `where` and `analyze deps` alike (page scripts are never run; bounded text scanners only):
  - `script-json`: `<script type="application/json">` and `application/ld+json` (Next.js `__NEXT_DATA__` included) as nodes `script[<n>]` (n counts such scripts in document order); paths continue as `script[0].$.props.pageProps.rows[0].amount`. Over 4 MiB a script is not decoded (`truncated`); malformed JSON is `unparsed`.
  - `inline-assign`: top-level `window.X = <literal>` / `var|let|const X = <literal>` in inline scripts, the literal an object or array in JSON or a tolerant superset (unquoted identifier keys, single-quoted strings, trailing commas, `undefined` as null), as `assign[X]` with paths such as `assign[__STATE__].rows[0].amount`. Function calls, expressions, template strings and assignments inside functions are not decoded. At most 64 per document and 1 MiB per literal; a literal that does not parse is `unparsed` with its first 80 characters quoted.
  - `viewstate`: hidden `__VIEWSTATE`, `__VIEWSTATEGENERATOR`, `__EVENTVALIDATION` and `javax.faces.ViewState` fields as `viewstate[<name>]` (the value as sent, so `deps` links a posted viewstate to the page that held it) and, base64-decoded (2 MiB per field), `{bytes: {length, sha256}, strings}` where `strings` are the printable ASCII and UTF-16LE runs of at least 4 characters, in order and de-duplicated. No .NET LOS / Java object-graph decoding.
- A decoded node's text is left out of the literal match on the rest of the document, so a value both carried in a script and shown in a table cell is reported once per place. `find` hits inside a node carry `node` (step, address, and a script's `id` / `type`); nodes that were not decoded are listed in `searched.embedded`. `where` ranks embedded candidates with the JSON ones, before the page's own text nodes.
- Range scenario s41 embedded-state in the end-to-end suite.

### Fixed

- `analyze deps` (and `analyze chain`, `replay export-python`) orders two requests on the monotonic clock (`timing.start`, `timing.responseStart`, the body at `mono`) and falls back to the wall clock only when one side has none. Each request's wall `ts` is anchored on its own CDP `wallTime`, and a response read ~2 ms before the next request could come out after it on the wall clock, so a token taken from that response (s07's `x-csrf` from the login body) lost its source and showed as `computed-in-page` (seen once on Windows CI).
- `emulate --network-conditions` now throttles on a session that is not recording: Chrome applies throttling only while the Network domain is on, so an emulated preset keeps it on for the tab until a later `emulate` clears it, and neither `wait --idle` nor `net stop` turns it off underneath. Measured on the range site: a 300 KB fetch under "Slow 3G" took about 8 s (lower bound 6 s from the preset's 50000 B/s) where it used to take 1 ms without a recording, and it stays throttled after `wait --idle` and after `net stop`.

### Trace mode: which page scripts read which browser signals (0.4-F)

- **`tabcap trace start [--apis <file>] [--stack 8] [--first-n 20] [--max-hits 500]`**, `trace stop`, `trace status`, `trace list [--api <name>] [--script <url>] [--text]`. Session-scoped and explicit: once on, every current and future tab, iframe (out-of-process ones included) and dedicated worker of the session is traced until `trace stop` or `session stop`. Read-only: debugger breakpoints (`Debugger.setBreakpointOnFunctionCall`, installed in the `scriptFirstStatement` instrumentation pause before a document's first script runs) record which script and line read each API; nothing in the page is injected, wrapped or changed. Breakpoints make scripts slower and the timing is observable — `trace start` and `trace status` say so, and while trace mode is on every command's answer carries `"trace":"on"`.
- New bundle event kind **`signal`** (docs/04 §4.1): one per (document, api, caller location) with `count`, `firstMono` / `lastMono`, a stack of up to `--stack` frames for the first `--first-n` events of each (api, caller), `truncated: true` once an API hit `--max-hits` in one document (its breakpoint is then removed for that document), and `value` read once per document and API in tabcap's isolated world (≤ 1 KB inline, else a blob; cookies, storage and form values are `"<not-recorded>"`; secrets replaced). Reads triggered by a tabcap `evaluate` are tagged `caller.kind: "tabcap"`. Canvas / WebGL error / audio context instrumentation events are `signal`s with `access: "event"`.
- `manifest.mode.trace` is `false` or the trace settings (`mechanism`, `apis` = sha256 of the active signal list, `stack`, `firstN`, `maxHits`); `manifest.traceWindows` lists the `note` events that opened and closed each trace window.
- The built-in list covers navigator, screen, time zone, canvas, WebGL, speech voices and font checks (names only; `$TABCAP_HOME/config/signals.json` or `--apis` override it: a JSON array of up to 500 names). Names missing in the browser are skipped and listed by `trace status`; on Chrome for Testing 155 that is `Window.prototype.devicePixelRatio` (an own accessor of the global object, not on the prototype chain).
- While the session waits for the human (`waiting`), trace mode skips every debugger pause (`Debugger.setSkipAllPauses`) and says `"trace":"paused"`; `handoff continue` resumes it. Both are `note` events.
- Known gaps: reads issued after a navigation has started are not recorded; Service Workers and Shared Workers are not traced.

### Native wire-fingerprint component (0.4-W1)

- **`native/wireprint/`** (Zig 0.16.0, Apache-2.0 like the rest of the repo): the wire-level fingerprint tool joins the repository as a native component. It reads pcaps, raw TLS records and HTTP/2 client streams and computes ClientHello fields, JA3, JA4 (`_r` / `_o` / `_ro`), HTTP/2 SETTINGS / WINDOW_UPDATE / pseudo-header order, HPACK-decoded headers and the Akamai string, plus profile assembly, cross-layer consistency checks and a layer-grouped diff. `bun run test:native` runs its offline tests (`zig build test -Dopenssl=false`), `bun run fmt:native` formats it, and CI builds it on Linux, Windows and macOS and cross-compiles it for darwin-arm64, linux-x64, linux-arm64 and windows-x64 (not shipped in the release packages yet). Only `-Dopenssl=false` is built: the old `serve` echo server stays in the source but is not compiled. The JA4H / JA4T code and its `-Dja4plus` option were deleted before import. Browser profiles (`corpus/`) will come only from the Chrome for Testing version tabcap ships. Third-party notices (JA3, JA4, RFC 7541 tables) are in NOTICE.

### Sites, credentials and the guard

- **Site and account store**: `tabcap site add <name> --url <entry> --user <account> [--domains a,b]` reads the password at a prompt or from a pipe (`--password-stdin`), never from an argument; `tabcap site list` shows names, entry URLs, domains, account names and references, never passwords; `tabcap site remove`. The store is `~/.config/tabcap/state.db` (bun:sqlite, plain text, file 0600 in a 0700 directory; the daemon refuses to start when permissions are wider).
- **Filling credentials by reference**: `tabcap fill <ref> --secret <site>.password|username` lets the daemon fill the value. Stored passwords appear as `<secret:<site>.password>` in every command output, the daemon log, `snapshot` / `evaluate` results and the bundle's `cmd` events; only the login request body itself keeps the value, and HAR export and `bundle redact` redact it. `tabcap session start <name> --site <site>` binds a site to the session, and the bundle manifest records `session.site` / `session.account`.
- **One login per session**: a second `fill --secret …password` for the same site in the same session returns `guard.login-limit` and leaves the page alone; `--confirm` lets it through. Each decision is a `guard` event.
- **Hand-off on verification pages**: while recording, an HTML 403 answering an API call or a page load puts the session into `waiting` (with a reason and a screenshot path); commands that act on the page then return `waiting` until the human finishes and runs `tabcap handoff continue`; `tabcap handoff status` shows the state. The bundle has `guard` (breaker) and `handoff` (waiting / resumed) events. Only this one challenge form is recognised so far, and only while `net start` records.
- **External handler interface**: `~/.config/tabcap/plugins/<name>/manifest.json` describes an out-of-process handler (one JSON object on stdin and one on stdout, any language); `tabcap plugin list | enable | disable`. On a challenge, enabled handlers are asked first: an answer resumes the session and goes to the agent, otherwise the human gets it; every call is a `cmd` event pair (actor `system`, secrets replaced). tabcap itself ships no handler.
- New error codes `waiting` and `guard.login-limit`; error envelopes may carry extra fields (`waiting` has `state`, `reason`, `screenshot`).

### Replay

- **Offline replay server**: `tabcap replay serve <bundle> [--port 4500]` listens on loopback only and matches on method + path + sorted query + request body sha256; it answers with the recorded status, headers (without hop-by-hop headers, `content-length` and `content-encoding`; `set-cookie` kept) and body. Several recordings of the same key are answered in recorded order (pagination); `x-tabcap-replay: r-12;n=2` names the recording; a recording without a body answers its status with an empty body and `x-tabcap-replay-missing`; a same-origin `location` becomes a path so redirects stay on the replay server. No match → 404 with up to 3 nearest recordings and what differs. `--strict <headers>` and `--match-cookies` widen the match.
- **Field-by-field check**: `tabcap replay check <bundle> --against <origin>` sends the recorded requests again and compares status, selected headers and body (JSON per path, text equal, binary by hash), prints a table (`--json` for the envelope) and exits 1 on any difference. Loopback only by default; a non-loopback target needs `--live`, a stored site whose domains match, and is paced per site (one request per 2 s by default, `--rate`).
- **Session export**: `tabcap replay session <bundle> -o storage-state.json` writes the bundle's latest cookie snapshot as a Playwright storageState file (or, with `--site`, the session saved in the store), mode 0600, without printing values.
- **Python client generator**: `tabcap replay export-python <bundle> -o <dir>` writes an httpx client (one function per request group; constants baked in, session values from storageState, timestamps made at call time, varying values as arguments, responses as `TypedDict`s), fixtures, a pytest suite that runs against `replay serve` and a Chinese README. Signature-like parameters and encrypted bodies are not reproduced: those functions raise `NotImplementedError` (`TODO: computed in the page; see docs/03 §6`).
- **Cookie snapshots in the bundle**: each tab writes a `state` event (`what: "cookies"`; the CDP `Network.getCookies` array stored as a blob; the event itself has only `origin`, `count`, `reason`) at `net start`, after every page navigation and at `net stop`, so `replay session` works on real recordings.
- **Site sessions in the store**: a session started with `--site` saves that site's cookies in the store at `tabcap session stop` and `tabcap handoff continue` (only counts are printed); `tabcap replay session --site <site> -o …` needs no bundle. Saved cookie values of 8+ characters are replaced with `<secret:<site>.cookie.<name>>` in all output, like passwords.
- **Per-host replay**: when a bundle spans several hosts, the match key includes the host: a request whose `Host` header is a recorded host matches only that host's recordings; any other `Host` matches as before. `--json` reports it in `match.host` and `routes[].host`.

### Input fidelity

- **Trusted click**: `tabcap click <ref> --trusted` now clicks like a person: focus emulation and a paint check, then a 100–400 ms mouse path that ends exactly on the element centre, press, 50–140 ms, release; Chrome builds the pointer and mouse events, all `isTrusted:true`, pointerdown `pressure` 0.5. The output adds `eventShape:"full"`, `trajectory` and `pressGapMs`. A tab that cannot be confirmed painted gets no mouse move: DOM click and `degraded:"not-painted"`. A move without an answer returns the new error code `move-timeout` and nothing is pressed. Nothing is ever retried automatically; `not-delivered` no longer suggests trying again.
- **The default click is unchanged but says what it is**: plain `click` is still the DOM `el.click()` and now reports `eventShape:"incomplete"` with a warning (one untrusted `click`, no pointer / mouse events).
- **Per-key typing**: `tabcap type <text> --trusted` presses one key per character (keydown, keypress, beforeinput, input, keyup, all trusted); characters without a US-layout key (CJK, emoji) are inserted one by one; `--delay <ms>` between characters, default 0. The default `type` and the new `--insert` still insert the whole text at once and report `eventShape:"insert"` with a warning.
- **Responses the page never reads**: when the page never reads a body, Chrome sends no finished event and the request used to wait until `net stop`; now, 1 s after the response arrived and once Fetch interception has the full body, it is written as `finished` with `unreadByPage: true`, `bodySource: "fetch"` and no end time, visible to `net list` / `net show` / `net wait` and the guard while recording.

### Platforms, CI and packaging

- **Linux x64 and Windows x64 code paths** (macOS behaviour is unchanged). Linux: the default directories follow XDG (`$XDG_CONFIG_HOME/tabcap`, `$XDG_CACHE_HOME/tabcap`, `$XDG_DATA_HOME/tabcap`; the old `~/.config` / `~/.cache` / `~/.local/share` paths when unset), and `tabcap setup` unpacks with `unzip`, or `bsdtar` when `unzip` is missing. Windows: everything lives under `%LOCALAPPDATA%\tabcap\{config,cache,data}`; the daemon listens on 127.0.0.1 with a random port and a bearer token made at every start, both written to `config\daemon.json`, where the CLI reads them (the token is never logged, never on a command line and never in `daemon status`; requests without it get 401); `tabcap setup` downloads the `win64` build, unpacks it with PowerShell `Expand-Archive` and checks the binary's version resource (`chrome.exe --version` prints nothing on Windows); the store and plugin directories are not permission-checked there (no POSIX modes on Windows: the files keep the user-default ACL of `%LOCALAPPDATA%`); handing the foreground back (macOS `osascript`) is skipped with a log line.
- **Linux: trusted input on background tabs, cookie snapshot at navigation**. A background tab that focus emulation makes visible is drawn by nobody on Linux, and after a few changed frames Chrome gives it one frame per second, so `click --trusted` / `hover` moves timed out (`move-timeout`). The paint check now also measures the frame rate; when frames are slow, a tiny screencast keeps the tab drawn from before the first move until after the release, and the output says so (`paint: {frameMs, held: "screencast"}`). macOS tabs paint at full rate and are not affected. The `nav` cookie snapshot now asks `Network.getCookies` for the committed URL: without `urls` Chrome could answer from a frame tree that did not have the new URL yet and return no cookies.
- `tabcap daemon status` gains `listener` (`unix` or `tcp`) and, on Windows, `port`; `socket` is null there. `tabcap setup --platform` accepts `win64`.
- **Binaries and packages**: `bun run release` builds `tabcap-darwin-arm64`, `tabcap-linux-x64`, `tabcap-linux-arm64` and `tabcap-windows-x64.exe` (Bun cross-compilation) and packs each as `tabcap-v<version>-<platform>.tar.gz` (`.zip` for Windows) with the binary, the skill, `README.md` and `README.zh-CN.md` (quick start only), `LICENSE` and `NOTICE`, a `.sha256` per package and one `SHA256SUMS`.
- **CI** (GitHub Actions): unit tests, typecheck and skill validation on Linux, Windows and macOS; end-to-end tests on Linux (Xvfb) and Windows with Chrome for Testing from `tabcap setup`, cached by version; a `v*` tag builds the four packages on their runners (linux-arm64 cross-compiled) and creates a draft release, which is never published automatically.
- **Packaging templates** in `packaging/` (not published anywhere): a Homebrew formula (macOS arm64), an npm wrapper with one optional dependency per platform and a shim without install scripts, a Scoop manifest.
- The repository checks out with LF line endings on every OS (`.gitattributes`); fixtures and generated docs are compared byte for byte.

### Fixes and housekeeping

- Screenshot and wrap-up order: right after a background tab rendered new content Chrome sometimes answered a screenshot with "Unable to capture screenshot", so the `waiting` screenshot of the verification wall was empty (the occasional s15 end-to-end failure since 0.3-A); such captures are now retried with focus emulation (as a single-colour capture already was). Unfinished requests closed at stop or navigation are written in start order (they were written in parallel and could swap).
- `timing.responseStart` now comes from CDP ResourceTiming (the same clock as `end`), so it is no longer later than `end`; HAR exports and salt files from `bundle export har` are 0600; `tabcap type` returns `stale-ref` when the focused element was removed or re-rendered (focus fell back to `<body>`) instead of silently typing nothing.
- `BBL_*` environment variables are no longer read: only `TABCAP_HOME`, `TABCAP_CHROME`, `TABCAP_SESSION`, `TABCAP_LOG` and the other `TABCAP_*` names.
- The bundle reader keeps a request's `postDataMissing`; the store is at schema 2 (`guard_counters` counts requests, for `replay check --live` pacing).

## 0.2.0 (2026-10-15)

- **Renamed**: `bbl` is now `tabcap`: binary, skill, default directories (`~/.config/tabcap`, `~/.cache/tabcap`, `~/.local/share/tabcap`) and environment variables (`TABCAP_HOME`, `TABCAP_CHROME`, `TABCAP_SESSION`, `TABCAP_LOG`). 0.2.x still reads the old `BBL_*` variables (removed in 0.3). Old directories are not migrated: run `tabcap setup` again, or rename `~/.config/bbl` and the others.
- **Waiting**: `tabcap wait --text | --selector | --url | --idle | --fn` waits for a page condition; `tabcap net wait --url` waits until a request came back with its body. A timeout says what was still outstanding.
- **Console**: `tabcap console` shows a tab's console and uncaught exceptions (with a short stack), keeping the last 500 entries even when not recording.
- **Recording**: WebSocket frames go into the bundle (`net list --kind ws`, `net body r-12:34`); so does the console; every command is recorded as a start / end event pair; a request without a response records `status` null.
- **Offline analysis**: `tabcap analyze find <bundle> <text>` finds which request, frame or console line carries a text, through decode chains (base64, gzip, URL encoding, JSON escapes …), and lists responses that look encrypted when nothing is found (entropy thresholds by length); `tabcap analyze diff <bundle1> <bundle2>` compares parameters across recordings: constant, per session, timestamp, varying. `--save` writes the result back into the bundle.
- **Command table export**: `tabcap schema --json` prints every command, argument and option with types, defaults, help and examples, for other agents and tools.
- HAR export leaves out `cmd` and `console` events and counts them in `dropped`.

Fixes from the trial report (also 0.2.0):

- **Popups no longer keep the foreground**: a window or foreground tab opened by `window.open` brings Chrome to the macOS front; tabcap now notices and hands the foreground back to the app that had it (`tabcap browser status` counts it in `popupFocus`). It does not interfere while you yourself are using that browser.
- **Popups can be driven**: they appear in `tabcap tabs` (`reason: popup`, `opener`); a popup of a tab the session opened belongs to the session too and closes with `session stop`. Every tab command takes `--tab t2`; `tabcap tab use t2` switches the current tab.
- **No fake success**: after the page re-rendered an element, `click` / `fill` with its old ref return `stale-ref` (snapshot again) instead of reporting a click that did nothing.
- **`tabcap net show <id>`**: one request in full: request headers, request body (over 2 KB: a file path plus the first 2 KB), response headers, body path, timing, initiator `url:line:col`, navigation and tab, outcome; `r-12:34` shows a WebSocket frame.
- **`net list` is no longer drowned in noise**: failed requests (e.g. a page scanning ports) and `data:` URLs are hidden by default but always counted (`total`, `shown`, `hidden: {failed, data}`); `--failed` shows only the failed ones, `--all` everything; new `--host`, `--status 4xx`, `--method`, `--tab`, `--since c-12`, `--limit` (default 100) and `--offset` paging.
- **`net wait` looks back to the last action**: it counts from the latest action command (navigate / click / fill / type / press / go / reload / evaluate), so `click → wait --text → net wait` no longer times out; `--since start` covers the whole recording, `--fresh` only new requests; a timeout lists earlier finished matches. Action commands return their `cmd` id while recording.
- **`find` lists clickable hits first**: for custom checkboxes, `div role=none` buttons and the like, `find` points at the element that really has the click listener or a hand cursor; click its `clickable` ref.
- **`evaluate` returning a Promise** gives `needs-await` (add `--await`) instead of `{}`.
- Two-level help such as `tabcap net list --help`, group help `tabcap net --help`, and `tabcap --version`.
- `tabcap setup` removes half-finished downloads from an interrupted run and leaves no temporary directory when a download fails.
- Bundle files are readable by their owner only (files 0600, directories 0700); events record actor `ai` by default, and requests the page sends on its own after a navigation are no longer recorded as `human`.

## 0.1.0 (2026-10-15)
